## Objetivo e orientação vigente

Diagnosticar a mensagem “Você não tem permissão para esta operação” durante login no cockpit para a identidade administrativa existente. Não alterar senha, sessão, papel, organização, tokens, segredos ou envios. Manter `DISPATCHES_PAUSED=true`; sem DMs, OAuth ou commit/push.

## Diagnóstico verificado

- `SessionStore.login` exige `Origin` exatamente igual a `PUBLIC_APP_URL` (`same_origin` em `apps/api/auth.py`). Diferença entre `http://127.0.0.1:8000` e a origem HTTPS configurada causa HTTP 403 antes da autenticação. A interface atualmente apresenta todos os 403 como “Você não tem permissão para esta operação”, mesmo quando o motivo real é origem não autorizada.
- `.env.local` foi carregado sem imprimir valores sensíveis; `PUBLIC_APP_URL` está configurada para um host `trycloudflare.com`. O host completo não é reproduzido aqui por ser temporário. A recomendação anterior de abrir o cockpit local pode, portanto, produzir essa divergência.
- Consulta somente de leitura ao Supabase, fora do sandbox restrito: identidade Auth encontrada e não excluída; existe exatamente um vínculo `admin`. Nenhum UUID, email, segredo ou dado pessoal foi escrito neste registro. Logo, o usuário não precisa ser provisionado/promovido novamente.
- Inspeção de processos não encontrou API Uvicorn nem `cloudflared` ativos no ambiente no momento desta sessão. A tentativa de conexão Supabase dentro do sandbox havia falhado por DNS; a consulta escalada conseguiu concluir a leitura.

## Ação operacional recomendada

Abrir o cockpit pela mesma origem pública HTTPS definida em `PUBLIC_APP_URL`, usando `/m0/connect`, e manter API e túnel ativos. Não usar `127.0.0.1` enquanto `PUBLIC_APP_URL` aponta ao túnel. Como quick tunnel é temporário, se o túnel tiver sido recriado, configurar `PUBLIC_APP_URL`, `API_PUBLIC_URL` e `META_OAUTH_REDIRECT_URI` com o host efetivamente emitido; reiniciar a API e alinhar o callback no painel Meta antes de reconectar. Não inventar/reutilizar domínio sem confirmar que está ativo. A origem atual só foi lida de `.env.local`; disponibilidade pública não foi verificada nesta sessão.

Se o login falhar novamente usando a origem correspondente, coletar apenas o status HTTP e o `error.code`/mensagem sanitizada da resposta de `/api/v1/auth/login`; não copiar senha, cookies ou tokens. A resposta do backend diferencia `Origem não autorizada` de `Usuário sem acesso ao cockpit`, mas o cliente atual mascara ambos.
